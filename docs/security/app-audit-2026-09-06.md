# 앱 보안 점검 (2026-09-06)

학기 일정표([`docs/plan/schedule.md`](../plan/schedule.md))의 9월 행이 보안 취약점 점검을 약속한다. 그때까지 이 저장소의 보안 관련 작업은 화면 단위로 흩어져 있었고([#41](https://github.com/Team-CareerCompass/CareerCompass-FE/issues/41)·[#50](https://github.com/Team-CareerCompass/CareerCompass-FE/issues/50)), 앱 전체를 한 번 훑은 적이 없었다. 이 문서가 그 기록이다.

점검 대상은 `develop` 의 69db375 다. GitHub Actions 공급망은 별도 문서([`actions-supply-chain.md`](actions-supply-chain.md))가 다룬다.

## 고친 것

### 원문 보기가 서버가 준 주소를 스킴 검증 없이 열었다

`PostingRawScreen` 은 공고 상세의 `url` 을 그대로 `Intent.ACTION_VIEW` 에 넘겼다. 이 값은 서버가 준 것이지만 그 서버도 사용자가 등록한 게시판을 크롤러로 긁어 채운다. 게시판 쪽에서 심은 문자열이 앱까지 그대로 온다는 뜻이다. `ACTION_VIEW` 는 스킴에 따라 브라우저가 아니라 다른 앱의 딥링크를 여니, 원문 보기 버튼이 무엇을 열지 서버가 정하게 된다. 도메인 모델의 불변식도 `url` 이 비지 않았는지만 봤다.

`core:common` 에 `ExternalUrl` 을 두고 `http`·`https` 와 호스트가 있는 주소만 통과시킨다. 스킴이 없는 값은 보완하지 않고 거절한다. 서버 값에 앱이 스킴을 붙여 주면 무엇을 열지 앱이 추측하는 셈이다. 거절한 경우 사용자에게는 열기 실패와 같은 안내를 보이고, 계약 위반이므로 리포팅에는 결함으로 남긴다. 주소 전체가 아니라 스킴만 싣는다.

사용자가 입력하는 게시판 주소는 이전부터 `feature:feed:domain` 의 `BoardUrl` 이 같은 두 스킴으로 잠가 왔다. 이번에 서버가 주는 값 쪽이 같은 기준을 갖게 됐다.

## 확인한 것

| 항목 | 판정 | 근거 |
|---|---|---|
| 평문 HTTP | 차단 | `app/src/main/AndroidManifest.xml` 의 `usesCleartextTraffic="false"`. 디버그 소스셋에 완화 선언이 없다 |
| 네트워크 로그 | 안전 | `NetworkModule.kt:79` 이 `HttpLoggingInterceptor` 를 `BuildConfig.DEBUG` 일 때만 `BODY`, 아니면 `NONE` 으로 둔다 |
| 로그 유출 | 안전 | 프로덕션 소스의 `android.util.Log` 호출은 `LocalStoreRegistryImpl` 두 곳뿐이고 예외 클래스 이름만 남긴다 |
| 백업 | 차단 | `allowBackup="false"`. `backup_rules.xml`·`data_extraction_rules.xml` 이 함께 있다 |
| 딥링크 | 안전 | `AppDeepLinkParser` 가 스킴·호스트·경로 세그먼트 수·양의 정수 id 를 모두 검사하고 어긋나면 null 이다. 인증 게이트는 `AppNavigation` 이 잡고 소비되지 않은 딥링크는 세션 종료 때 버린다 |
| 익스포트된 컴포넌트 | 최소 | release 에 남는 것은 `MainActivity`(런처·딥링크)와 카카오 SDK 의 OAuth 핸들러뿐이다. `DebugSettingsActivity` 는 디버그 소스셋에만 있다 |
| 파일 업로드 | 검증함 | `UploadFileReader` 가 확장자로 형식을, `MAX_PAST_APPLICATION_FILE_BYTES` 로 크기를 거른다. 크기를 못 읽으면 거절한다 |
| 광고 식별자 | 제거 | 매니페스트가 `AD_ID`·`ACCESS_ADSERVICES_AD_ID` 를 `tools:node="remove"` 로 뺀다. Analytics·FCM 자동 초기화도 꺼져 있다 |
| 저장소의 비밀값 | 없음 | `git ls-files` 에 keystore·`google-services.json`·`local.properties` 가 없고 `.gitignore` 가 넷 다 막는다. 소스에 박힌 키 문자열도 없다 |
| 의존성 취약점 | 판정 완료 | Dependabot 경고 8건은 전부 빌드 도구의 전이 의존성이고 앱 런타임에 들어가지 않는다 |

## 확인하지 못한 것

- 인증서 고정(`CertificatePinner`)은 쓰지 않는다. 서버 도메인과 인증서가 아직 없어 고정할 대상이 없다. 서버가 서면([BE #7](https://github.com/Team-CareerCompass/CareerCompass-BE/issues/7)) 그때 필요 여부를 판단한다.
- 인증·인가의 서버 쪽 점검은 이 문서 범위가 아니다. [BE #53](https://github.com/Team-CareerCompass/CareerCompass-BE/issues/53) 이 맡는다.
- R8 축소 뒤 실기기 동작은 릴리스 빌드로 확인해야 한다. 스토어 자산과 함께 [#263](https://github.com/Team-CareerCompass/CareerCompass-FE/issues/263) 에서 본다.
