# FCM 토큰의 생애 (§1 · §8 · F2-4)

> 푸시 토큰이 **언제 서버로 가고 언제 사라지는가**를 정한 문서다. API_SPEC v0.1 에는 등록과 해제만 있고
> **갱신이 없다.** 없는 자리를 각자 메우면 앱과 서버가 다른 규칙으로 같은 토큰을 다루게 되므로 여기서
> 먼저 정하고 서버 저장소에 옮긴다. 정본 우선순위는 [`canon.md`](canon.md).

토큰을 잃으면 알림이 조용히 끊긴다. 사용자에게는 「앱이 알림을 안 준다」로만 보이고, 앱에도 서버에도
오류가 남지 않는다. 그래서 네 시점을 빠짐없이 정해 둔다.

## 네 시점

| 시점 | 무엇이 일어나는가 | 계약 | 지금 상태 |
| --- | --- | --- | --- |
| 등록 | 로그인할 때 토큰을 함께 보낸다 | `POST /auth/social/{provider}` 요청의 `fcmToken`(§1) | 계약에 있다. 앱은 **아직 보내지 않는다** — 아래 「동의가 먼저다」 |
| 갱신 | FCM 이 토큰을 바꾸면 서버에 다시 알린다 | **없다.** 아래에서 정한다 | 계약 없음 ([BE #44](https://github.com/Team-CareerCompass/CareerCompass-BE/issues/44)) |
| 해제 | 로그아웃하면 그 기기의 토큰을 지운다 | `POST /auth/logout` 이 「토큰 무효화 + FCM 토큰 해제」를 함께 한다(§1) | 계약에 있고 앱도 부른다 |
| 정리 | 발송이 `UNREGISTERED` 로 실패한 토큰을 서버가 버린다 | 서버 몫 | [BE #44](https://github.com/Team-CareerCompass/CareerCompass-BE/issues/44) |

로그아웃 해제는 앱이 따로 할 일이 없다. `AuthRepository.logout()` 이 세션을 지우기 **전에**
`POST /auth/logout` 을 부르므로 그 요청에 살아 있는 토큰이 실리고, 서버가 그 기기의 FCM 토큰을 함께
푼다. 네트워크가 실패해도 로컬 세션은 정리된다(best-effort) — 그때 서버에 남은 토큰은 위의 「정리」가
발송 실패로 걷어낸다.

## 갱신 엔드포인트 — 앱이 제안하는 계약

```
POST /auth/fcm-token
{ "deviceId": "uuid-v4", "fcmToken": "fcm-token-string" }
→ 200 { "ok": true }
```

- **`/auth` 아래에 둔다.** 등록(§1 소셜 로그인)과 해제(§1 로그아웃)가 이미 인증 쪽에 있다. 토큰은 알림
  설정이 아니라 **세션과 기기에 매인 값**이라 §8 로 가면 「설정을 바꾸지 않았는데 설정 API 를 부른다」가
  된다.
- **`deviceId` 를 함께 보낸다.** 서버는 토큰을 사용자×기기 단위로 저장한다(BE #44). 기기 식별자는 소셜
  로그인·지문 등록이 이미 쓰는 값이고 앱에 `DeviceIdentityProvider` 로 서 있다. 없으면 같은 계정의 다른
  기기 토큰을 덮어써 한쪽 기기가 알림을 잃는다.
- **같은 값을 다시 보내도 성공이다.** `onNewToken` 은 재설치·복원·앱 데이터 삭제에서도 불리고, 앱은 그
  값이 서버가 아는 것과 같은지 알 수 없다. 중복 호출이 실패하면 앱이 실패를 재시도하며 같은 요청을
  반복한다.
- **로그인 상태에서만 부른다.** 로그아웃 상태에서 받은 새 토큰은 보낼 곳이 없다 — 다음 로그인의
  `POST /auth/social/{provider}` 가 그때의 토큰을 실어 보내므로 따로 저장해 둘 필요가 없다.

## 동의가 먼저다

앱은 지금 로그인 요청에 `fcmToken = null` 을 보낸다(`SocialLoginUseCase`). 토큰을 자동으로 만들어 보내면
사용자가 알림을 허락하기 전에 기기가 발송 대상이 되기 때문이다(FE #41). Android 13+ 의
`POST_NOTIFICATIONS` 동의 흐름이 서면 그 뒤에 토큰을 붙인다 — 수신 서비스·권한 요청·`onNewToken` 은
FE [#197](https://github.com/Team-CareerCompass/CareerCompass-FE/issues/197) 의 몫이고, 이 문서는 그
이슈가 구현할 계약을 미리 못 박아 둔 것이다.

## 이 문서가 정하지 않는 것

- 발송 파이프라인·채널·문구 — 서버(BE #44·#47)와 FE #197.
- 알림 종류별 설정(`GET/PUT /notifications/settings`)은 토큰과 무관하다. 토큰이 없어도 설정은 저장된다.
